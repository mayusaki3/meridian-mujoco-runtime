# システム同定(sysid)をどう扱うか

MuJoCo上のシミュレーション精度を向上するため、システム同定(sysid)機能を提供したい。  

本システムでは、利用者が手持ちのモーター、サーボモーター、ロボットの機構を含む駆動装置等の実測データを元に sysid を実行し、その結果をシミュレーションへ反映できるようにする。

sysidの最優先目標は、同定結果だけでなく、同定に使用した設定・実験環境・測定データ・同定方法を再現可能な形で共有し、OSSとして他の利用者が結果を再利用したり、同じ環境を使って再実験したり、設定や同定方法を改良・流用できるようにすることである。

## sysid の利用経路

sysidの利用開始は、大きく次の2系統を想定する。

### Robotから対象を選択する

Project内のRobotから、サーボモーター等の単体部品、またはギア・関節・リンク等を含む機構上の範囲を選択し、sysid対象とする。

Robotの物理構成とsysidの実行単位は同一である必要はなく、利用者が構成部品からsysid実行単位を編集できるようにする。

### Motor / Servo等を登録して単体で実行する

Robotへ組み込む前の市販モーターやサーボモーター等を登録し、単体のsysid対象として使用できるようにする。

市販製品の単体sysidで得られた結果は、同一製品を使用するRobot内の対象へ適用できるようにする。製品単体の結果、特定個体の結果、Robot機構を含めて同定した結果は適用範囲を区別し、対象構成や測定条件が異なる結果を無条件に同一視しない。

両経路は対象の決定後、共通のsysid設定・計測・Simulation・Identification・Validation・Result保存処理を利用する。

## sysid設定と共有

sysid設定では、少なくとも次の内容を編集・保存・再利用できることを目標とする。

- 構成部品とsysid実行単位
- 実対象へ与える動作パターン・入力条件
- 計測する入力・出力
- 現在の実装値
- 固定する値と同定対象とする値
- 同定対象値の初期値や制約
- 計測・制御方法
- Simulation条件
- Identification方法
- Validation条件

保存したsysid設定・実験環境は、特定の実行結果だけに閉じず、別Projectや別対象へ再利用・共有できるようにする。

sysid実行では、実測データと同じ入力条件でSimulationを行い、実測結果との差を評価し、選択したパラメータを調整してSimulationを繰り返す構成を想定する。System Identificationでは入力・出力の測定、モデル構造と調整対象parameterの選択、推定、モデル評価を反復するため、Meridianでも測定データ、同定設定、結果を分離して再利用可能にする。

## sysid の対応例

- アクチェーター特性
  - PID応答
  - トルク特性
  - 速度特性
  - 制御遅延
  - デッドゾーン
  - 個体差

- ロボット組み立て状態
  - 関節摩擦
  - 重量バランス
  - 慣性変化
  - 配線や機構による負荷
  - 組み立て精度差

- シミュレーション環境
  - 接地摩擦
  - 床材特性
  - 外乱条件

## sysid の使い方イメージ

本システムでは、以下のような使い方を想定している。

### 1. sysid対象の初期定義  

Project内の対象Robot / Actuator / Field等と、それらに関連付けられたMJCF等のResourceを使用し、対象の種類や必要なパラメータ定義（角度や電圧、計算式内の変数など）を行う。  
ここで定義したパラメータ（MJCF custom等を含む）がsysidの結果を反映する対象になる。  
必要なら、メッシュなども作成する。  
MuJoCo標準ではない計算が必要な場合は、custom関数呼び出しを定義できる。
custom関数呼び出しをMJCFで定義した場合、該当する custom関数が無ければ作成が必要。
custom関数には、MuJoCo上での次ステップ計算関数と、sysid時の同定評価関数が含まれる。

### 2. 計測対象と制御方法を決定  

既存の計測プローブがあれば選択、なければ新規に計測プローブを作成する。
- 計測対象は、計測プローブが対応しているMJCFに定義したパラメータ（角度や電圧など）。  
- 計測プローブが対応するMJCFと、定義されたどのパラメータに対応するかは、計測プローブの開発者が自由に決めてよい。

既存の制御ドライバがあれば選択、なければ新規に制御ドライバを作成する。 
- 制御方法は、PWMやシリアルコマンドによるモーション再生、電圧制御などで、MJCFでパラメータ定義されたものとなる。 
- 制御ドライバ次第で、CSV入力でも実マイコンからの入力でも対応できる。
- 制御ドライバが対応する入力や制御対象は、制御ドライバの開発者が自由に決めてよい。

計測プローブ、制御ドライバは、Runtime から呼び出す想定。
どちらも Runtime に対して、どの MJCF の どのパラメータにアクセスするかを公開する必要がある。

### 3. 実対象を制御し、計測を行う  

計測開始で、Runtime は MJCF で定義されたパラメータセットを作成し、制御ドライバが終了するまで制御ドライバが設定したデータと計測プローブにより収集されたデータを更新しながら結果を記録する。  
観測周期は 0.1 ms間隔 (10kHz) が理想。そのため実マイコンで計測・バッファリングし、USBやWiFiでPCに転送する必要があるかもしれない。

### 4. シミュレーション対象を制御し、sysidを行う  

sysid開始で、Runtime は、収集されたデータに含まれる制御ドライバによる指令値で MuJoCo のパラメータセットを更新し、シミュレーションを行う。
指令値がなくなるまで Runtime はその結果を収集し保存する。

3.で収集された結果と、4.で収集された結果の誤差が少なくなるよう、計算式内の変数パラメータ調整を繰り返す。

一定の誤差内に収まったとき、同定結果を保存し、必要に応じてProject内の対象やMJCF等の表現へ適用してsysidが終了する。保存時には、結果だけでなく、使用したsysid設定・対象・測定条件・測定データとの関係を保持し、再現・比較・共有に利用できるようにする。
custom関数内の処理を変更し、再実行のケースも想定したい。
